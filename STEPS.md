# Start the Restaurant App with a QR Code

The QR code and the website work without internet. The computer running Node.js and the customer's phone only need to be connected to the same local Wi-Fi network. Internet is only needed to download Node dependencies the first time.

## 1. Open the project folder

Open PowerShell and run:

```powershell
cd C:\xampp\htdocs\restaurant-api
```

## 2. Install dependencies

Run this once:

```powershell
npm install
```

Run this as its own command. Do not join it to `npm start`.

## 3. Start the server

Run:

```powershell
npm start
```

Run each command separately. For example, do not type `npm startcd C:\xampp\htdocs\restaurant-api` as one command.

If you see `EADDRINUSE` or `address already in use :::3000`, the server is already running. Do not start another copy; open `http://localhost:3000/` in the browser instead.

The app runs on port `3000`.

## 4. Find your computer's Wi-Fi IP address

Open a second PowerShell window and run:

```powershell
ipconfig
```

Find the `IPv4 Address` under your active Wi-Fi connection. It will look similar to:

```text
192.168.1.23
```

## 5. Test the app on your computer

Open this address in your browser, replacing the IP address with yours:

```text
http://192.168.1.23:3000
```

## 6. Open the app on your phone

Connect your phone to the same Wi-Fi network as the computer. Then open this address on the phone:

```text
http://192.168.1.23:3000
```

Do not use `localhost` on the phone. `localhost` refers to the device that opens the address.

## 7. Create a QR code for the app

Open this address on your computer, replacing the IP address with yours:

```text
http://192.168.178.86:3000/api/qrcode?url=http%3A%2F%2F192.168.178.86%3A3000%2F
```

A QR-code image will appear. Scan it with your phone's camera.

The QR image is generated by this project itself at `/api/qrcode`, so it does not use Google or any other internet service. The landing page's **Download JPG** link uses `/api/qrcode.jpg` to download a branded JPG with the Pawn logo in the center.

After a customer places an order, the confirmation page also displays a QR code for that order. It can be scanned on the same Wi-Fi network to open the order details.

## 8. Customer ordering process

1. The customer scans the app QR code.
2. The customer sees all available restaurants and food stalls.
3. The customer selects a restaurant and presses `Add` beside a food item.
4. The cart shows the selected food, quantities, and total.
5. The customer enters a name, optional phone number, and pickup time.
6. The customer presses `Continue to payment` and enters demo card details.
7. The simulated transaction succeeds before the order is confirmed.
8. The app shows the paid order number, total, pickup time, order details link, and order QR code.

## 9. If the phone cannot connect

- Make sure the phone and computer use the same Wi-Fi network.
- Keep the PowerShell window running the server open.
- Allow Node.js through Windows Firewall on **Private networks** if Windows asks.
- Check that the IP address has not changed by running `ipconfig` again.
- Confirm the server is running at `http://localhost:3000` on the computer.

If port `3000` is already in use, the app may already be running. Open `http://localhost:3000` on the computer before starting another copy.

## 10. Stop the server

In the PowerShell window running the server, press:

```text
Ctrl+C
```

## 11. Pawn pickup and refunds

Open the staff pickup page:

```text
http://localhost:3000/restaurant-site/pawn-pickup-dashboard.html
```

The page asks for staff authorization before it opens. For this demo, use username `4321` and password `4321`. The same authorization protects the pickup-order API. This works from the XAMPP project folder as well as the Node server because the login page and static assets are in `C:\xampp\htdocs\restaurant-api`.

The page checks for new orders every 10 seconds. Staff can mark an order as collected. Picked-up orders and expired uncollected orders remain recorded for four hours, then are automatically removed by the running app.

The queue displays orders 10 through 100. For an eligible pending or recently expired order, **Refund order** removes the order from the database and refreshes the queue immediately.

Customers can request a refund for an expired order from the order-details page using the order number, name, and phone number used to place the order. Refund requests are accepted for two hours after the order expires. The app records the refund request; actual payment transfer must still be handled by the business payment provider.
